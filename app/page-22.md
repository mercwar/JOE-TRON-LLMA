# Comprehensive Appendix, Glossary, and Index: Native Windows GGUF Runtime Architecture

This unified reference document provides the technical appendix, terminology glossary, and structural index for building, compiling, and operating a native C GGUF runtime on Windows.

---

## Part 1: Appendix — Build & Environment Reference

### 1. Master Compilation Cheat Sheet

To compile the unified C runtime (`main.c`) against your local engine artifacts in an MSYS2 UCRT64 environment, execute the following command:

```bash
gcc main.c -o fire-gem-runtime.exe -I./include -L./lib -luser32 -lkernel32 -llama -lggml

```

### 2. Required Project Directory Structure

Ensure your workspace matches this directory layout prior to compilation:

```text
/my-gguf-studio/
│
├── models/
│   └── active_model.gguf    <-- Target single-file GGUF weight container
│
├── include/                 <-- Header files exported from llama.cpp / MercWar setup
│   ├── llama.h
│   └── ggml.h
│
├── lib/                     <-- Precompiled static library binaries
│   ├── llama.lib
│   └── ggml.lib
│
└── main.c                   <-- Sovereign C runtime entry point

```

## Part 2: Glossary of Low-Level AI Terms

| Term | Definition in C / GGUF Architecture |
| --- | --- |
| **`libllama`** | The core C library providing high-level abstractions for model loading, tokenization, context allocation, and evaluation loops. |
| **`GGML`** | The underlying tensor math library optimized for low-memory overhead and high-speed CPU vector instruction sets (AVX2, AVX-512). |
| **`GGUF`** | A binary file format designed for storing transformer model weights, tensor tensors, and vocabulary metadata in a single self-contained file. |
| **`mmap` (Memory Mapping)** | A Win32/POSIX operating system feature that maps file contents directly into virtual memory address space, avoiding heavy RAM heap copies. |
| **`Logits`** | The multi-dimensional array of raw, unnormalized statistical prediction scores generated by the model for every token in its vocabulary. |
| **`Prefill Phase`** | The initial parallel batch evaluation pass (`llama_decode`) that processes incoming prompt tokens to populate the attention graph. |
| **`KV Cache`** | The Key-Value cache stored in the execution context (`llama_context`), retaining past attention states so the model remembers conversation history. |
| **`EOG / EOS`** | End-of-Generation or End-of-Stream token IDs that signal to the runtime dispatch loop when text generation should gracefully terminate. |
